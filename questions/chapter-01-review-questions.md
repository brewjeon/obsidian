# Chapter 01 Review Questions

## 1. 일반 Java Main과 Spring Boot 시작 클래스는 무엇이 다른가

일반 Java `main` 메서드는 JVM이 실행할 진입점일 뿐이다. 개발자가 객체 생성, 설정 로딩, 서버 실행 같은 흐름을 직접 구성해야 한다.

Spring Boot 시작 클래스는 `main` 메서드에서 `SpringApplication.run(...)`을 호출한다. 이때 Spring Boot는 애플리케이션 컨텍스트를 만들고, 컴포넌트 스캔을 수행하고, 자동 설정을 적용하고, 웹 애플리케이션이라면 내장 서버를 실행한다.

설명 핵심:

Spring Boot 시작 클래스는 단순 실행 진입점이 아니라, Spring 컨테이너와 자동 설정, 내장 웹 서버를 띄우는 부트스트랩 지점입니다.

## 2. `BUILD SUCCESSFUL`과 웹 서버 실행은 무엇이 다른가

`BUILD SUCCESSFUL`은 컴파일, 테스트, 패키징 같은 빌드 작업이 성공했다는 뜻이다. 코드가 문법적으로 맞고 설정된 테스트가 통과했다는 의미에 가깝다.

웹 서버 실행은 애플리케이션이 실제 프로세스로 떠서 포트를 열고 HTTP 요청을 받을 수 있는 상태가 됐다는 뜻이다.

설명 핵심:

빌드 성공은 코드와 빌드 파이프라인의 성공이고, 서버 실행은 런타임에서 애플리케이션이 실제 요청을 처리할 준비가 됐다는 뜻입니다. 둘은 연결되어 있지만 같은 검증은 아닙니다.

## 3. `/health` 테스트와 실제 HTTP 호출은 각각 무엇을 검증하는가

`/health` 테스트는 코드 내부에서 컨트롤러가 기대한 HTTP 상태와 JSON 응답을 만드는지 검증한다. 빠르고 반복 가능하며 기능 변경 시 회귀를 잡는 데 좋다.

실제 HTTP 호출은 애플리케이션을 실행한 뒤 외부 클라이언트가 실제 포트로 요청했을 때 응답이 오는지 검증한다. 서버 실행, 포트 바인딩, 라우팅, 네트워크 경로를 포함한 더 넓은 범위를 확인한다.

설명 핵심:

테스트는 코드 수준의 빠른 보증이고, 실제 HTTP 호출은 실행 환경을 포함한 엔드투엔드에 가까운 확인입니다. 두 검증은 목적이 다르기 때문에 초기 프로젝트에서는 둘 다 해보는 것이 좋습니다.
